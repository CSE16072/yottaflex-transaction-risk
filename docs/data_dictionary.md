# Data Dictionary – YottaFlex Transaction Risk Intelligence

This document describes the purpose of each database entity.

| Table | Description |
|---|---|
| customers | Stores customer identity and status information. |
| accounts | Stores customer account details, balances and account lifecycle status. |
| merchants | Stores merchant information used during transaction monitoring. |
| devices | Stores device information associated with customer activity. |
| transactions | Stores transaction amounts, timestamps, account references and transaction status. |
| transfer_links | Connects debit and credit transaction legs for transfer reconciliation. |
| risk_rules | Stores configurable rules used to identify suspicious transactions. |
| alerts | Stores risk alerts generated by monitoring rules. |
| cases | Stores investigation records and their dispositions. |
| case_alerts | Connects alerts to investigation cases. |
| analyst_actions | Records actions performed during case investigation. |

## Key Relationships

- One customer can have multiple accounts.
- Accounts are associated with transactions.
- Transactions can reference merchants and devices.
- Transfer links connect related transaction legs.
- Risk rules can generate multiple alerts.
- Cases can contain multiple alerts through case_alerts.
- Analyst actions are associated with investigations.

## Data Integrity

- Primary keys uniquely identify records.
- Foreign keys connect related entities.
- Lifecycle and status fields support transaction and investigation workflows.
- Ground-truth anomaly labels are maintained separately in `data/ground_truth.csv`.

## Data Classification

All generated records are synthetic. The ground-truth dataset is intended for validation and evaluation, not as an input feature for risk scoring.
